# open-cpu

**Бібліотека виявлення набору інструкцій CPU та диспетчеризації під час
виконання** (Rust), спільна для екосистеми `aon-co-jp`.

Створена для того, щоб `open-raid-z` / `aruaru-db` / `aruaru-llm` / `open-cuda`
не писали кожен свій власний дубльований код виявлення можливостей CPU.

**Це не резидентний сервіс (не демон).** Це звичайний бібліотечний крейт, який
кожен репозиторій додає до `[dependencies]` свого `Cargo.toml` і лінкує
всередину того самого процесу.

## Що вона вміє

1. **Виявлення можливостей CPU під час виконання** — `open_cpu::detect()`
   повертає `&'static CpuCapabilities`. Використовує
   `std::is_x86_feature_detected!` і кешує результат першого виявлення в
   `OnceLock`, тож вартість повторних викликів близька до нуля.
2. **Диспетчеризація операцій RAID6 GF(2^8) під час виконання** — залежно від
   результату виявлення під час виконання обирається скалярна / PCLMULQDQ /
   AVX2 / AVX-512 реалізація.

## Використання

```toml
# 依存側の Cargo.toml
[dependencies]
open-cpu = { path = "../open-cpu" }
```

```rust
// 1. CPU 機能検出
let caps = open_cpu::detect();
println!("{}", caps);   // Display 実装あり
// => sse2 ssse3 popcnt aes pclmulqdq bmi1 bmi2 fma sha avx2

if caps.avx2 { /* ... */ }
if caps.has_all(&[caps.avx2, caps.fma]) { /* AVX2+FMA3 の経路 */ }

// 2. RAID6 パリティ(係数テーブル方式)
let d0 = vec![1u8; 4096];
let d1 = vec![2u8; 4096];
let mut p = vec![0u8; 4096];
let mut q = vec![0u8; 4096];
open_cpu::raid6_parity(&[&d0, &d1], &mut p, &mut q);

// 3. RAID-Z3 相当の P/Q/R(ホーナー法、係数テーブル不要で高速)
let mut r = vec![0u8; 4096];
open_cpu::raid6_parity3(&[&d0, &d1], &mut p, &mut q, &mut r);

// 個別 API
open_cpu::gf_xor(&mut p, &d0);                 // p ^= d0          (P パリティ)
open_cpu::gf_mul_parity(&mut q, &d0, 0x02);    // q ^= d0 * 0x02   (Q パリティ)
open_cpu::gf_mul2_xor(&mut q, &d0);            // q = q*2 ^ d0     (ホーナー法)
open_cpu::gf_mul4_xor(&mut r, &d0);            // r = r*4 ^ d0     (ホーナー法)

// ログ 1 行サマリ
println!("{}", open_cpu::runtime_summary());
// => open-cpu 0.1.0 | features: ... | gf impl: Avx2
```

### Перелік публічного API

| API | Зміст | Диспетчеризація |
|---|---|---|
| `detect() -> &'static CpuCapabilities` | Виявлення можливостей CPU (кеш `OnceLock`) | — |
| `runtime_summary() -> String` | Однорядкове зведення: результат виявлення + обрана реалізація | — |
| `selected_impl() -> GfImpl` | Реалізація, обрана для операцій GF | — |
| `gf_xor(dst, src)` | `dst ^= src` (парність P) | AVX2 / скалярна |
| `gf_mul_parity(dst, src, factor)` | `dst ^= src * factor` (парність Q) | AVX-512 (opt-in) / AVX2 / PCLMULQDQ / скалярна |
| `gf_mul_pow2_xor(acc, src, times)` | `acc = acc * 2^times ^ src` | AVX2 / скалярна |
| `gf_mul2_xor` / `gf_mul4_xor` | Те саме за `times=1` / `times=2` | Так само |
| `raid6_parity(stripes, p, q)` | Пакетний розрахунок P/Q методом таблиці коефіцієнтів | Згідно з вищезазначеним |
| `raid6_parity3(stripes, p, q, r)` | Пакетний розрахунок P/Q/R методом Горнера | Згідно з вищезазначеним |
| `gf_mul(a, b) -> u8` | Однобайтове множення в GF (`const fn`) | — |
| `gf_mul2_byte(b) -> u8` | Подвоєння одного байта в GF (`const fn`) | — |
| `raid6_coeff(i) -> u8` | Коефіцієнт RAID6 `g^i` (`g = 2`) | — |

Також опубліковано версії `*_scalar` / `*_avx2` / `*_pclmul` / `*_avx512`, що
дозволяють викликати кожну реалізацію явно (для бенчмарків і взаємної
перевірки; SIMD-версії — `unsafe`).

## Набори інструкцій, що виявляються

| Набір інструкцій | Виявлення | Використання в цьому крейті |
|---|---|---|
| SSE2 | ✅ | Використовується як допоміжний засіб для шляху PCLMULQDQ |
| SSSE3 | ✅ | `pshufb` (зведення в шляху PCLMULQDQ) |
| PCLMULQDQ | ✅ | Множення GF(2^8) (реалізація через множення без перенесень) |
| AVX2 | ✅ | Множення GF(2^8) (split-table на `vpshufb`, обирається за замовчуванням) |
| AVX-512F / BW / VL | ✅ | Шлях множення GF(2^8) є (**виконання не перевірено**, див. нижче) |
| POPCNT | ✅ | Лише виявлення (реалізації, що його використовує, немає) |
| BMI1 / BMI2 | ✅ | Лише виявлення (реалізації, що його використовує, немає) |
| FMA3 | ✅ | Лише виявлення (реалізації, що його використовує, немає) |
| AES-NI | ✅ | Лише виявлення (реалізації, що його використовує, немає) |
| SHA-NI | ✅ | Лише виявлення (реалізації, що його використовує, немає) |
| AVX-VNNI | ✅ | Лише виявлення (для майбутнього AI-висновування, реалізації немає) |
| AVX-512 VNNI | ✅ | Лише виявлення (для майбутнього AI-висновування, реалізації немає) |

На архітектурах, відмінних від x86/x86_64, усі поля стають `false`, і
відбувається відкат до скалярної реалізації (збірка при цьому проходить).

## Подробиці реалізації GF(2^8)

Незвідний многочлен — `0x11d` (x^8+x^4+x^3+x^2+1), твірний елемент — `g = 2`.
Те саме, що в Linux md/RAID6 та в ZFS RAID-Z.

- **Скалярна**: еталонна реалізація на таблицях nibble split (16 записів × 2).
- **PCLMULQDQ**: якщо розгорнути кожен байт з інтервалом 16 біт, то добуток без
  перенесень із 8-бітним коефіцієнтом (щонайбільше 15 біт) не переноситься до
  сусіднього слота. Використовуючи цю властивість, однією інструкцією множиться
  одразу 4 байти, після чого результат зводиться до GF(2^8) двома
  застосуваннями `pshufb`. 16 byte/iter.
- **AVX2**: реалізація split-table на `vpshufb`. 32 byte/iter.
- **AVX-512F/BW**: та сама split-table, обробка по 64 byte/iter.

## Виміряні бенчмарки

`cargo run --release --example bench` (4 MiB × 50 разів = 200 MiB, factor=0x8d)

Машина розробки: **AMD Ryzen 9 3950X** / Windows 11 / rustc 1.96.0

```
open-cpu 0.1.0 | features: sse2 ssse3 popcnt aes pclmulqdq bmi1 bmi2 fma sha avx2 | gf impl: Avx2
scalar   :  207.5 ms     963 MiB/s
pclmulqdq:  109.0 ms    1835 MiB/s  (1.90x vs scalar)
avx2     :   11.4 ms   17473 MiB/s  (18.14x vs scalar)
avx512   : このCPUでは未搭載のため実測不可(未検証)

xor scalar     :  11.5 ms   17451 MiB/s
xor dispatch   :   9.7 ms   20616 MiB/s  (1.15〜1.25x vs scalar)

horner scalar  :  51.5 ms    3880 MiB/s
horner dispatch:  14.8 ms   13521 MiB/s  (2.70〜3.52x vs scalar)
```

**Про розкид виміряних значень (чесний запис)**: за чотирьох послідовних
запусків коефіцієнт прискорення AVX2 для множення в GF коливався в діапазоні
**11,6–18,1 раза**, метод Горнера — **2,70–3,52 раза**, XOR — **1,12–1,25
раза** (скалярна сторона стабільно трималася близько 207 ms). Оскільки
SIMD-сторона сягає 10 000–20 000 MiB/s і **впирається в пропускну здатність
пам'яті**, на неї легко впливають стан кешу та інші процеси. Наведена вище
таблиця — це результат одного запуску як є, і коректніше сприймати коефіцієнти
як діапазон.

- **Множення в GF(2^8) на довільний коефіцієнт на AVX2 дає 11,6–18,1 раза
  відносно скалярної версії (за вимірюваннями)**. Це працює на шляху парності Q
  та відновлення в RAID6.
- **Метод Горнера — 2,70–3,52 раза (за вимірюваннями)**. Оскільки скалярна
  версія вже оптимізована бітовими трюками на u64, різниця не така велика, як
  для множення в GF.
- **Простий XOR — 1,12–1,25 раза**. Уже скалярна версія (u64) впирається в
  пропускну здатність пам'яті, тож запасу для SIMD мало (як і передбачалося).
- PCLMULQDQ дає 1,90 раза і має сенс **лише як запасний варіант для старих CPU,
  де AVX2 недоступний**.

## Стан перевірки (чесне розкриття)

- ✅ **Скалярна / PCLMULQDQ / AVX2**: перевірені виконанням на зазначеній
  машині розробки. У `cargo test` коректність скалярної реалізації
  перевіряється відносно наївної реалізації на бітових зсувах, а потім
  відносно скалярної реалізації перевіряється збіг вихідних даних реалізації
  PCLMULQDQ (**усі 256 варіантів коефіцієнта × 9 варіантів довжини**) та
  реалізації AVX2 (8 варіантів коефіцієнта × 11 варіантів довжини, включно з
  обробкою залишку). Усі 15 тестів + 2 doctest проходять.
- ⚠️ **Шлях AVX-512 не перевірено виконанням**. Оскільки машина розробки
  (Ryzen 9 3950X) не має AVX-512, перевірено **лише те, що компіляція
  проходить**. З міркувань безпеки він не обирається диспетчеризацією за
  замовчуванням і вмикається лише за opt-in, якщо задано змінну середовища
  `OPEN_CPU_ENABLE_AVX512=1`. Такий режим зберігається доти, доки не буде
  виконано перевірку на машині з AVX-512.
- ⚠️ Для POPCNT/BMI1/BMI2/FMA/AES-NI/SHA-NI/VNNI **є лише поля виявлення**;
  реалізацій обчислень, що їх використовують, поки немає.

| Репозиторій | Використання |

| [`open-raid-z`](https://github.com/aon-co-jp/open-raid-z) | Виявлення можливостей CPU, множення GF(2^8), XOR і метод Горнера (шлях AVX2) у `zfs_accel_hlsl/src/simd.rs` делеговані цьому крейту. Після міграції всі наявні 39 тестів проходять, числові значення повністю збігаються. |
| [`open-english`](https://github.com/aon-co-jp/open-english) | Однорядкове зведення в журналі запуску сервера та `GET /v1/cpu-runtime` (повертає набір інструкцій CPU виконавчої платформи у JSON). |

GPU).
