# open-cpu

**کتابخانهٔ تشخیص مجموعه‌دستورات CPU و ارسال (dispatch) در زمان اجرا** (Rust)،
مشترک در کل اکوسیستم `aon-co-jp`.

این کتابخانه برای جلوگیری از تکرار کدِ تشخیص قابلیت‌های CPU که
`open-raid-z` / `aruaru-db` / `aruaru-llm` / `open-cuda` هر کدام جداگانه
می‌نوشتند، ایجاد شد.

**یک سرویس مقیم (دیمن) نیست.** یک crate کتابخانه‌ای معمولی است که هر مخزن آن را
به `[dependencies]` در `Cargo.toml` اضافه می‌کند و درون همان فرایند لینک می‌شود.

## توانایی‌ها

1. **تشخیص قابلیت‌های CPU در زمان اجرا** — `open_cpu::detect()` مقدار
   `&'static CpuCapabilities` برمی‌گرداند. از `std::is_x86_feature_detected!`
   استفاده می‌کند و نتیجهٔ نخستین تشخیص را در `OnceLock` کش می‌کند، بنابراین
   هزینهٔ فراخوانی‌های مکرر تقریباً صفر است.
2. **ارسال زمان‌اجرا برای محاسبات RAID6 GF(2^8)** — بر پایهٔ نتیجهٔ تشخیص،
   پیاده‌سازی اسکالر / PCLMULQDQ / AVX2 / AVX-512 در زمان اجرا انتخاب می‌شود.

## نحوهٔ استفاده

```toml
# 依存側の Cargo.toml
[dependencies]
open-cpu = { path = "../open-cpu" }
```

```rust
// 1. CPU 機能検出
let caps = open_cpu::detect();
println!("{}", caps);   // Display 実装あり
// => sse2 ssse3 popcnt aes pclmulqdq bmi1 bmi2 fma sha avx2

if caps.avx2 { /* ... */ }
if caps.has_all(&[caps.avx2, caps.fma]) { /* AVX2+FMA3 の経路 */ }

// 2. RAID6 パリティ(係数テーブル方式)
let d0 = vec![1u8; 4096];
let d1 = vec![2u8; 4096];
let mut p = vec![0u8; 4096];
let mut q = vec![0u8; 4096];
open_cpu::raid6_parity(&[&d0, &d1], &mut p, &mut q);

// 3. RAID-Z3 相当の P/Q/R(ホーナー法、係数テーブル不要で高速)
let mut r = vec![0u8; 4096];
open_cpu::raid6_parity3(&[&d0, &d1], &mut p, &mut q, &mut r);

// 個別 API
open_cpu::gf_xor(&mut p, &d0);                 // p ^= d0          (P パリティ)
open_cpu::gf_mul_parity(&mut q, &d0, 0x02);    // q ^= d0 * 0x02   (Q パリティ)
open_cpu::gf_mul2_xor(&mut q, &d0);            // q = q*2 ^ d0     (ホーナー法)
open_cpu::gf_mul4_xor(&mut r, &d0);            // r = r*4 ^ d0     (ホーナー法)

// ログ 1 行サマリ
println!("{}", open_cpu::runtime_summary());
// => open-cpu 0.1.0 | features: ... | gf impl: Avx2
```

### فهرست API عمومی

| API | توضیح | ارسال (dispatch) |
|---|---|---|
| `detect() -> &'static CpuCapabilities` | تشخیص قابلیت‌های CPU (کش `OnceLock`) | — |
| `runtime_summary() -> String` | خلاصهٔ یک‌خطی از نتیجهٔ تشخیص + پیاده‌سازی انتخاب‌شده | — |
| `selected_impl() -> GfImpl` | پیاده‌سازی انتخاب‌شده برای محاسبات GF | — |
| `gf_xor(dst, src)` | `dst ^= src` (توازن P) | AVX2 / اسکالر |
| `gf_mul_parity(dst, src, factor)` | `dst ^= src * factor` (توازن Q) | AVX-512 (opt-in) / AVX2 / PCLMULQDQ / اسکالر |
| `gf_mul_pow2_xor(acc, src, times)` | `acc = acc * 2^times ^ src` | AVX2 / اسکالر |
| `gf_mul2_xor` / `gf_mul4_xor` | همان مورد بالا با `times=1` / `times=2` | همان بالا |
| `raid6_parity(stripes, p, q)` | محاسبهٔ یکجای P/Q به روش جدول ضرایب | مطابق موارد بالا |
| `raid6_parity3(stripes, p, q, r)` | محاسبهٔ یکجای P/Q/R به روش هورنر | مطابق موارد بالا |
| `gf_mul(a, b) -> u8` | ضرب GF یک‌بایتی (`const fn`) | — |
| `gf_mul2_byte(b) -> u8` | دوبرابرکردن یک بایت روی GF (`const fn`) | — |
| `raid6_coeff(i) -> u8` | ضریب RAID6 یعنی `g^i` (`g = 2`) | — |

نسخه‌های `*_scalar` / `*_avx2` / `*_pclmul` / `*_avx512` که هر پیاده‌سازی را
صریحاً فرا می‌خوانند نیز منتشر شده‌اند (برای بنچمارک و راستی‌آزمایی متقابل؛
نسخه‌های SIMD `unsafe` هستند).

## مجموعه‌دستورات هدفِ تشخیص

| مجموعه‌دستور | تشخیص | کاربرد در این crate |
|---|---|---|
| SSE2 | ✅ | به عنوان کمکی برای مسیر PCLMULQDQ |
| SSSE3 | ✅ | `pshufb` (کاهش در مسیر PCLMULQDQ) |
| PCLMULQDQ | ✅ | ضرب GF(2^8) (پیاده‌سازی ضرب بدون رقم نقلی) |
| AVX2 | ✅ | ضرب GF(2^8) (`vpshufb` split-table، انتخاب پیش‌فرض) |
| AVX-512F / BW / VL | ✅ | مسیر ضرب GF(2^8) وجود دارد (**اجرای آن راستی‌آزمایی نشده**، پایین‌تر را ببینید) |
| POPCNT | ✅ | فقط تشخیص (پیاده‌سازی استفاده‌کننده وجود ندارد) |
| BMI1 / BMI2 | ✅ | فقط تشخیص (پیاده‌سازی استفاده‌کننده وجود ندارد) |
| FMA3 | ✅ | فقط تشخیص (پیاده‌سازی استفاده‌کننده وجود ندارد) |
| AES-NI | ✅ | فقط تشخیص (پیاده‌سازی استفاده‌کننده وجود ندارد) |
| SHA-NI | ✅ | فقط تشخیص (پیاده‌سازی استفاده‌کننده وجود ندارد) |
| AVX-VNNI | ✅ | فقط تشخیص (برای استنتاج AI در آینده، پیاده‌سازی استفاده‌کننده وجود ندارد) |
| AVX-512 VNNI | ✅ | فقط تشخیص (برای استنتاج AI در آینده، پیاده‌سازی استفاده‌کننده وجود ندارد) |

در معماری‌هایی غیر از x86/x86_64 همهٔ فیلدها `false` می‌شوند و اجرا به
پیاده‌سازی اسکالر بازمی‌گردد (بیلد موفق است).

## جزئیات پیاده‌سازی GF(2^8)

چندجمله‌ای تحویل‌ناپذیر `0x11d` (x^8+x^4+x^3+x^2+1) و مولد `g = 2` است.
همانند Linux md/RAID6 و ZFS RAID-Z.

- **اسکالر**: پیاده‌سازی مرجع با جدول nibble split (۱۶ ورودی × ۲).
- **PCLMULQDQ**: اگر هر بایت با فاصلهٔ ۱۶ بیتی گسترده شود، حاصل‌ضرب بدون نقلی
  با ضریب ۸ بیتی (حداکثر ۱۵ بیت) به خانهٔ مجاور سرریز نمی‌کند. با استفاده از
  این ویژگی، ۴ بایت با یک دستور یکجا ضرب می‌شوند و سپس با دو بار `pshufb` به
  GF(2^8) کاهش می‌یابند. 16 byte/iter.
- **AVX2**: پیاده‌سازی split-table با `vpshufb`. 32 byte/iter.
- **AVX-512F/BW**: همان split-table با پردازش 64 byte/iter.

## بنچمارک اندازه‌گیری‌شده

`cargo run --release --example bench` (4 MiB × 50 بار = 200 MiB، factor=0x8d)

ماشین توسعه: **AMD Ryzen 9 3950X** / Windows 11 / rustc 1.96.0

```
open-cpu 0.1.0 | features: sse2 ssse3 popcnt aes pclmulqdq bmi1 bmi2 fma sha avx2 | gf impl: Avx2
scalar   :  207.5 ms     963 MiB/s
pclmulqdq:  109.0 ms    1835 MiB/s  (1.90x vs scalar)
avx2     :   11.4 ms   17473 MiB/s  (18.14x vs scalar)
avx512   : このCPUでは未搭載のため実測不可(未検証)

xor scalar     :  11.5 ms   17451 MiB/s
xor dispatch   :   9.7 ms   20616 MiB/s  (1.15〜1.25x vs scalar)

horner scalar  :  51.5 ms    3880 MiB/s
horner dispatch:  14.8 ms   13521 MiB/s  (2.70〜3.52x vs scalar)
```

**دربارهٔ پراکندگی مقادیر اندازه‌گیری‌شده (ثبت صادقانه)**: در چهار اجرای پیاپی،
نسبت شتاب AVX2 برای ضرب GF در بازهٔ **۱۱٫۶ تا ۱۸٫۱ برابر**، روش هورنر در بازهٔ
**۲٫۷۰ تا ۳٫۵۲ برابر** و XOR در بازهٔ **۱٫۱۲ تا ۱٫۲۵ برابر** نوسان داشت
(سمت اسکالر حدود 207 ms پایدار بود). سمت SIMD به 10000 تا 20000 MiB/s می‌رسد و
بنابراین **محدود به پهنای باند حافظه** است و به وضعیت کش و فرایندهای دیگر حساس
است. جدول بالا صرفاً نتیجهٔ یک اجرا را همان‌گونه که بود نشان می‌دهد، و درست‌تر
است که نسبت‌های شتاب را به صورت بازه در نظر بگیرید.

- **ضرب GF(2^8) با ضریب دلخواه در AVX2 نسبت به اسکالر ۱۱٫۶ تا ۱۸٫۱ برابر است
  (اندازه‌گیری‌شده)**. در مسیر توازن Q و مسیر بازیابی RAID6 مؤثر است.
- **روش هورنر ۲٫۷۰ تا ۳٫۵۲ برابر است (اندازه‌گیری‌شده)**. چون نسخهٔ اسکالر
  پیش‌تر با ترفندهای بیتی u64 بهینه شده، اختلاف به اندازهٔ ضرب GF نیست.
- **XOR ساده ۱٫۱۲ تا ۱٫۲۵ برابر است**. چون همان نسخهٔ اسکالر (u64) هم به پهنای
  باند حافظه چسبیده، فضای بهبود با SIMD کم است (مطابق انتظار).
- PCLMULQDQ ۱٫۹۰ برابر است و تنها **به عنوان بازگشتِ جایگزین برای CPUهای قدیمی
  که AVX2 ندارند** معنا دارد.

## وضعیت راستی‌آزمایی (افشای صادقانه)

- ✅ **اسکالر / PCLMULQDQ / AVX2**: روی ماشین توسعهٔ بالا با اجرا راستی‌آزمایی
  شده‌اند. در `cargo test`، درستی پیاده‌سازی اسکالر بر پایهٔ یک پیاده‌سازی سادهٔ
  مبتنی بر شیفت بیتی سنجیده شده، و سپس تطابق خروجی پیاده‌سازی PCLMULQDQ
  (**تمام ۲۵۶ ضریب × ۹ طول**) و پیاده‌سازی AVX2 (۸ ضریب × ۱۱ طول، شامل پردازش
  باقیمانده) با پیاده‌سازی اسکالر تأیید شده است. هر ۱۵ تست + ۲ doctest قبول شدند.
- ⚠️ **مسیر AVX-512 از نظر اجرا راستی‌آزمایی نشده است**. چون ماشین توسعه
  (Ryzen 9 3950X) فاقد AVX-512 است، **تنها موفق‌بودن کامپایل** تأیید شده است.
  برای ایمنی در ارسال پیش‌فرض انتخاب نمی‌شود و تنها در صورت تنظیم متغیر محیطی
  `OPEN_CPU_ENABLE_AVX512=1` به صورت opt-in فعال می‌شود. تا زمانی که
  راستی‌آزمایی روی ماشین دارای AVX-512 انجام شود، این رویکرد حفظ می‌شود.
- ⚠️ برای POPCNT/BMI1/BMI2/FMA/AES-NI/SHA-NI/VNNI **تنها فیلد تشخیص وجود دارد**
  و هنوز هیچ پیاده‌سازی محاسباتی که از آن‌ها استفاده کند موجود نیست.
