# open-cpu

**Библиотека определения набора инструкций CPU и диспетчеризации во время
выполнения** (Rust), общая для экосистемы `aon-co-jp`.

Создана для того, чтобы `open-raid-z` / `aruaru-db` / `aruaru-llm` / `open-cuda`
не писали каждый свой собственный дублирующийся код определения возможностей CPU.

**Это не резидентный сервис (не демон).** Это обычный библиотечный крейт,
который каждый репозиторий добавляет в `[dependencies]` своего `Cargo.toml`
и линкует внутрь того же процесса.

## Что она умеет

1. **Определение возможностей CPU во время выполнения** — `open_cpu::detect()`
   возвращает `&'static CpuCapabilities`. Использует
   `std::is_x86_feature_detected!` и кэширует результат первого определения в
   `OnceLock`, поэтому стоимость повторных вызовов близка к нулю.
2. **Диспетчеризация операций RAID6 GF(2^8) во время выполнения** — в
   зависимости от результата определения во время выполнения выбирается
   скалярная / PCLMULQDQ / AVX2 / AVX-512 реализация.

## Использование

```toml
# Cargo.toml на стороне зависимого проекта
[dependencies]
open-cpu = { path = "../open-cpu" }
```

```rust
// 1. CPU 機能検出
let caps = open_cpu::detect();
println!("{}", caps);   // Display 実装あり
// => sse2 ssse3 popcnt aes pclmulqdq bmi1 bmi2 fma sha avx2

if caps.avx2 { /* ... */ }
if caps.has_all(&[caps.avx2, caps.fma]) { /* AVX2+FMA3 の経路 */ }

// 2. RAID6 パリティ(係数テーブル方式)
let d0 = vec![1u8; 4096];
let d1 = vec![2u8; 4096];
let mut p = vec![0u8; 4096];
let mut q = vec![0u8; 4096];
open_cpu::raid6_parity(&[&d0, &d1], &mut p, &mut q);

// 3. RAID-Z3 相当の P/Q/R(ホーナー法、係数テーブル不要で高速)
let mut r = vec![0u8; 4096];
open_cpu::raid6_parity3(&[&d0, &d1], &mut p, &mut q, &mut r);

// 個別 API
open_cpu::gf_xor(&mut p, &d0);                 // p ^= d0          (P パリティ)
open_cpu::gf_mul_parity(&mut q, &d0, 0x02);    // q ^= d0 * 0x02   (Q パリティ)
open_cpu::gf_mul2_xor(&mut q, &d0);            // q = q*2 ^ d0     (ホーナー法)
open_cpu::gf_mul4_xor(&mut r, &d0);            // r = r*4 ^ d0     (ホーナー法)

// ログ 1 行サマリ
println!("{}", open_cpu::runtime_summary());
// => open-cpu 0.1.0 | features: ... | gf impl: Avx2
```

### Список публичного API

| API | Содержание | Диспетчеризация |
|---|---|---|
| `detect() -> &'static CpuCapabilities` | Определение возможностей CPU (кэш `OnceLock`) | — |
| `runtime_summary() -> String` | Однострочная сводка: результат определения + выбранная реализация | — |
| `selected_impl() -> GfImpl` | Реализация, выбранная для операций GF | — |
| `gf_xor(dst, src)` | `dst ^= src` (чётность P) | AVX2 / скалярная |
| `gf_mul_parity(dst, src, factor)` | `dst ^= src * factor` (чётность Q) | AVX-512 (opt-in) / AVX2 / PCLMULQDQ / скалярная |
| `gf_mul_pow2_xor(acc, src, times)` | `acc = acc * 2^times ^ src` | AVX2 / скалярная |
| `gf_mul2_xor` / `gf_mul4_xor` | То же при `times=1` / `times=2` | Так же |
| `raid6_parity(stripes, p, q)` | Пакетный расчёт P/Q методом таблицы коэффициентов | Согласно вышеуказанному |
| `raid6_parity3(stripes, p, q, r)` | Пакетный расчёт P/Q/R методом Горнера | Согласно вышеуказанному |
| `gf_mul(a, b) -> u8` | Однобайтовое умножение в GF (`const fn`) | — |
| `gf_mul2_byte(b) -> u8` | Удвоение одного байта в GF (`const fn`) | — |
| `raid6_coeff(i) -> u8` | Коэффициент RAID6 `g^i` (`g = 2`) | — |

Также опубликованы версии `*_scalar` / `*_avx2` / `*_pclmul` / `*_avx512`,
позволяющие вызвать каждую реализацию явно (для бенчмарков и взаимной
проверки; SIMD-версии — `unsafe`).

## Наборы инструкций, подлежащие определению

| Набор инструкций | Определение | Использование в этом крейте |
|---|---|---|
| SSE2 | ✅ | Используется как вспомогательное средство для пути PCLMULQDQ |
| SSSE3 | ✅ | `pshufb` (приведение в пути PCLMULQDQ) |
| PCLMULQDQ | ✅ | Умножение GF(2^8) (реализация через умножение без переносов) |
| AVX2 | ✅ | Умножение GF(2^8) (split-table на `vpshufb`, выбирается по умолчанию) |
| AVX-512F / BW / VL | ✅ | Путь умножения GF(2^8) есть (**выполнение не проверено**, см. ниже) |
| POPCNT | ✅ | Только определение (реализации, использующей его, нет) |
| BMI1 / BMI2 | ✅ | Только определение (реализации, использующей его, нет) |
| FMA3 | ✅ | Только определение (реализации, использующей его, нет) |
| AES-NI | ✅ | Только определение (реализации, использующей его, нет) |
| SHA-NI | ✅ | Только определение (реализации, использующей его, нет) |
| AVX-VNNI | ✅ | Только определение (для будущего AI-вывода, реализации нет) |
| AVX-512 VNNI | ✅ | Только определение (для будущего AI-вывода, реализации нет) |

На архитектурах, отличных от x86/x86_64, все поля становятся `false`, и
происходит откат к скалярной реализации (сборка при этом проходит).

## Подробности реализации GF(2^8)

Неприводимый многочлен — `0x11d` (x^8+x^4+x^3+x^2+1), порождающий элемент —
`g = 2`. То же самое, что в Linux md/RAID6 и в ZFS RAID-Z.

- **Скалярная**: эталонная реализация на таблицах nibble split
  (16 записей × 2).
- **PCLMULQDQ**: если развернуть каждый байт с интервалом 16 бит, то
  произведение без переносов с 8-битным коэффициентом (не более 15 бит) не
  переносится в соседний слот. Используя это свойство, одной инструкцией
  умножаются сразу 4 байта, после чего результат приводится к GF(2^8) двумя
  применениями `pshufb`. 16 byte/iter.
- **AVX2**: реализация split-table на `vpshufb`. 32 byte/iter.
- **AVX-512F/BW**: та же split-table, обработка по 64 byte/iter.

## Измеренные бенчмарки

`cargo run --release --example bench` (4 MiB × 50 раз = 200 MiB, factor=0x8d)

Машина разработки: **AMD Ryzen 9 3950X** / Windows 11 / rustc 1.96.0

```
open-cpu 0.1.0 | features: sse2 ssse3 popcnt aes pclmulqdq bmi1 bmi2 fma sha avx2 | gf impl: Avx2
scalar   :  207.5 ms     963 MiB/s
pclmulqdq:  109.0 ms    1835 MiB/s  (1.90x vs scalar)
avx2     :   11.4 ms   17473 MiB/s  (18.14x vs scalar)
avx512   : このCPUでは未搭載のため実測不可(未検証)

xor scalar     :  11.5 ms   17451 MiB/s
xor dispatch   :   9.7 ms   20616 MiB/s  (1.15〜1.25x vs scalar)

horner scalar  :  51.5 ms    3880 MiB/s
horner dispatch:  14.8 ms   13521 MiB/s  (2.70〜3.52x vs scalar)
```

**О разбросе измеренных значений (честная запись)**: при четырёх
последовательных запусках коэффициент ускорения AVX2 для умножения в GF
колебался в диапазоне **11,6–18,1 раза**, метод Горнера — **2,70–3,52 раза**,
XOR — **1,12–1,25 раза** (скалярная сторона стабильно держалась около 207 ms).
Поскольку SIMD-сторона достигает 10 000–20 000 MiB/s и **упирается в
пропускную способность памяти**, на неё легко влияют состояние кэша и другие
процессы. Приведённая выше таблица — это результат одного запуска как есть, и
корректнее воспринимать коэффициенты как диапазон.

- **Умножение в GF(2^8) на произвольный коэффициент на AVX2 даёт 11,6–18,1
  раза относительно скалярной версии (по измерениям)**. Это работает на пути
  чётности Q и восстановления в RAID6.
- **Метод Горнера — 2,70–3,52 раза (по измерениям)**. Поскольку скалярная
  версия уже оптимизирована битовыми трюками на u64, разница не так велика,
  как для умножения в GF.
- **Простой XOR — 1,12–1,25 раза**. Уже скалярная версия (u64) упирается в
  пропускную способность памяти, поэтому запаса для SIMD мало (как и
  предполагалось).
- PCLMULQDQ даёт 1,90 раза и имеет смысл **только как запасной вариант для
  старых CPU, где AVX2 недоступен**.

## Состояние проверки (честное раскрытие)

- ✅ **Скалярная / PCLMULQDQ / AVX2**: проверены выполнением на указанной
  машине разработки. В `cargo test` корректность скалярной реализации
  проверяется относительно наивной реализации на битовых сдвигах, а затем
  относительно скалярной реализации проверяется совпадение выходных данных
  реализации PCLMULQDQ (**все 256 вариантов коэффициента × 9 вариантов
  длины**) и реализации AVX2 (8 вариантов коэффициента × 11 вариантов длины,
  включая обработку остатка). Все 15 тестов + 2 doctest проходят.
- ⚠️ **Путь AVX-512 не проверен выполнением**. Поскольку машина разработки
  (Ryzen 9 3950X) не имеет AVX-512, проверено **только то, что компиляция
  проходит**. Из соображений безопасности он не выбирается диспетчеризацией по
  умолчанию и включается только по opt-in, если задана переменная окружения
  `OPEN_CPU_ENABLE_AVX512=1`. Такой режим сохраняется до тех пор, пока не будет
  выполнена проверка на машине с AVX-512.
- ⚠️ Для POPCNT/BMI1/BMI2/FMA/AES-NI/SHA-NI/VNNI **есть только поля
  определения**; реализаций вычислений, использующих их, пока нет.
